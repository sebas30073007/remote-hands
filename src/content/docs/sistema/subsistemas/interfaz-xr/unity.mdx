Este subsistema es el menos replicable de los tres, y conviene decirlo
pronto: **los scripts sueltos no reconstruyen la aplicación**. Un script de
Unity es un componente que se cuelga de un objeto de escena y recibe sus
referencias desde el inspector. Sin las escenas y los prefabs, lo que hay
aquí sirve para entender la lógica y el protocolo —que es mucho, y es
suficiente para escribir un cliente propio— pero no para compilar esta app.

## Stack

| Paquete | Función |
| --- | --- |
| Meta XR SDK (All-in-One) 83.0 | SDK principal, passthrough y controladores |
| AsyncZMQ (NetMQ) | Cliente ZeroMQ hacia la NUC |
| Unity XR Interaction Toolkit | Ray interaction y EventSystem VR/MR |
| TextMesh Pro | Toda la UI de texto |
| OVRInput | Lectura de joystick, botones y hápticos del controlador |

Los comandos que salen por el puerto `5002` se envían varias veces
seguidas, con unos milisegundos de separación. Es una defensa contra el
*slow joiner* de ZMQ: un suscriptor que acaba de conectarse pierde los
primeros mensajes que se publican, porque el enlace todavía no está
establecido. Repetir el comando hace que al menos una copia llegue.

La IP de respaldo está **incrustada en el componente**, así que en otra red
hay que cambiarla desde el inspector o introducirla con el teclado virtual la
primera vez.
